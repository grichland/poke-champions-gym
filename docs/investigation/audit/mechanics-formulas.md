## Primitives (SD sim\dex.ts:365, sim\battle.ts:2321-2410)

- `trunc(x)` = `x >>> 0` (JS ToUint32: floor for positives; NEGATIVE inputs wrap to ~4e9). `trunc(x, bits)` = `(x>>>0) % 2^bits`.
- `modify(v, num, den=1)`: `m = trunc(num*4096/den)`; result `trunc((trunc(v*m) + 2048 - 1) / 4096)`. That is multiply by m/4096, round HALF DOWN (adds 2047, not 2048). Example 1.5 -> m=6144; 1.3 -> m=trunc(5324.8)=5324; 0.5 -> 2048; 0.75 -> 3072; 1.2 -> 4915; 0.25 -> 1024; 2 -> 8192.
- `chainModify(num, den=1)` (battle.ts:2337): `prev = trunc(event.modifier*4096)`; `next = trunc(num*4096/den)`; `event.modifier = ((prev*next + 2048) >> 12) / 4096` (this chain step rounds half UP, unlike modify). The event modifier starts at 1 for each runEvent. At the END of runEvent (battle.ts:936-940), if relayVar is a non-negative integer number, `relayVar = modify(relayVar, event.modifier)` once. So all chainModify calls of one event name are combined first, then applied once to the value.
- A handler that RETURNS a number replaces relayVar immediately (e.g. `return this.modify(atk, 1.5)`); such returns are applied in handler order, interleaved with chainModify handlers (the chain is still applied once at the end on whatever relayVar is then).
- `finalModify(v)` (battle.ts:2397): `modify(v, event.modifier)` then resets modifier to 1; used where a handler wants to apply the chain mid-event.
- `randomizer(d)` (battle.ts:2407): `trunc(trunc(d * (100 - random(16))) / 100)`; random(16) uniform integer 0..15, so factor 100..85 percent, each 1/16.
- `clampIntRange(n, min, max)`: clamp, `trunc` not applied.
- Handler order within one event: speedSort by priority desc, then order, then speed (field/ability/item sub-order: Condition 2, Weather/Format 5, Ability 7, Item 8). Order only matters when a handler returns a value rather than chainModify, and for 16-bit/rounding interplay of returned values.

## Item 3. Base damage formula (battle-actions.ts:1769-1775)

```
L = attacker level (50)
tr = floor for non-negative
baseDamage = tr( tr( tr( tr(2*L/5) + 2 ) * BP * A ) / D ) / 50 )
```
Exact code: `tr(tr(tr(tr(2 * level / 5 + 2) * basePower * attack) / defense) / 50)`. NOTE the inner term is `tr(2*level/5 + 2)` (floor of the SUM; at L=50 it is exactly 22), then `* BP * A` (product of three integers, truncation only at the divisions), `tr(/ D)`, `tr(/ 50)`. `BP` here is the post-`BasePower` event integer (see item 2), `A`, `D` are the post-modify-event integers (item 1). Then `modifyDamage` adds 2 (below). Level for all mons is 50 (Adjust Level).
At L=50: baseDamage = floor(floor(22 * BP * A / D) / 50); then `+ 2` inside modifyDamage.

## Item 9. Recoil, drain, crash, Struggle, heal, residual amounts (rounding rule per source)

 - Direct damage helper `damage(d)`: `clampIntRange(d, 1)` (min 1 when d non-zero) then `target.damage` `trunc(d)` (floor) and cap by current HP. Heal helper `heal(d)`: `if (d && d <= 1) d = 1; trunc(d)`, capped at maxhp.
 - Recoil (battle-actions.ts:1435): `recoil = clamp(round(damageDealt * n / d), 1)` using `Math.round` (half up), where `damageDealt = move.totalDamage` = sum over hits of actual HP removed (after target HP cap; for Substitute hits, the sub damage dealt, line `applyRecoilDamage(damage, move, source)` in the Substitute handler). Applied once after the last hit. Struggle recoil = `clamp(round(baseMaxhp / 4), 1)`; Mind Blown/Chloroblast `round(maxhp / 2)` (not min-clamped, uses current maxhp). Life Orb recoil: `damage(source.baseMaxhp / 10)` -> floor, min 1 (fires in `onAfterMoveSecondarySelf` once per move USE if the move dealt damage and the user did not switch out).  - Drain (battle.ts:2187-2189 and the Substitute handler): `heal(Math.round(targetDamage * n / d))` where `targetDamage` is the damage actually dealt to the target (cap by HP); vs a Substitute: `Math.ceil(damage * n / d)` where damage is the sub damage dealt.  - Crash damage (Jump Kick etc. on miss/immune): `damage(source.baseMaxhp / 2)` -> floor, min 1 (move.hasCrashDamage).

## Item 10. Substitute interaction and "damage dealt"
