5. Minor, not a rules difference: engine table lacks `mirror`/`metronome` flags for both moves (the engine has no such flags in play).

## Notes

- Hyper Beam on the recharge turn when the opponent uses Sucker Punch / Thunderclap: Showdown fails them against a mustrecharge target (data\moves.ts:18404, 19505). The engine's recharge choice is Choices::NONE with default category Status (choices.rs:20657), so choice_effects.rs:625-629 sets BP 0. Equivalent result. Not a finding.
- Mirror Move / Me First style interactions with a recharging target (moves.ts:11548) are not modelled by the engine; belongs to those moves' slices, and they are mostly not in the Champions pool.
- The `remove_effects_for_protect` function does not clear `flags.recharge`; it is harmless only because the damage path is skipped when category becomes Status. If the core is rewritten so damage-path gating changes, Hyper Beam into Protect could wrongly set recharge. Worth a regression test.
- Edge not verified: recharging user whose opponent moves first with a switch-out move (U-turn): whether the saved second move for a NONE choice still clears MUSTRECHARGE was not traced (generate_instructions.rs:2216-2227 returns before the NONE branch is reached only when `!first_move && force_switch`; the NONE branch at 2063 comes first, so it appears to clear it). Confidence medium on that single sub-case.
- The earlier CSV heuristic ("volatile_status field missing") for hyperbeam is a false alarm: the engine implements the self-volatile through the `recharge` flag, not a table volatile_status field.
