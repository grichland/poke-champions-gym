Root: `C:\Users\user\Code\research\pcsa-rl\poke-engine-eval\poke-engine` (all paths below relative to it; `src/genx/...` means `src/genx/`). Read-only study, nothing was built or run. "Verified" = read in code with file:line. "Inferred" = my reasoning, not run.

## Summary
- This checkout is already Champions-aware: features `champions` and `bss` exist (`Cargo.toml:41-42`), with BSS team preview (60 options), Mega Evolution, Champions stat points, sleep/paralysis/thaw changes, Champions move edits. Tera is compiled out unless `terastallization` (gen9-only).
- It is an expectiminimax/MCTS engine. A turn returns `Vec<StateInstructions>` = every outcome branch with a probability and an undo-able instruction list (`src/instruction.rs:11-17`), never one sampled outcome.
- Random events branched: accuracy, paralysis full-para, thaw, sleep wake-up, confusion self-hit, Protect chain, secondaries/contact-ability effects, speed ties, drag target, Sleep Talk pick, crit (only in a restricted way).
- Collapsed: damage roll (always 0.925 x max, float), crit (ignored unless `branch_on_damage`), multi-hit count (fixed 3 / 6 / 5 / 4), Outrage/lock duration (always 3), confusion duration (never ends), most random-move effects (Metronome, Assist etc. are data-only no-ops).
- Damage is f32 math with one combined multiplier, not Showdown's integer chain; prior eval found 172/220 exact (see `notes/poke-engine-eval.md`).
- No hidden information model, no Struggle in options, PP only decremented when pp < 10, Disable has no effect on legality.
- State is a plain `Clone` struct (not Copy) holding 12 `Pokemon` x 4 `Move` each embedding a full `Choice` (with an `Option<Vec<Secondary>>` heap field): large and allocation-heavy to clone (inferred ~10-15 KB).
- Sampler hook: easiest is post-hoc sampling of the returned Vec (already done in `pe_ext/src/lib.rs:22-33`); a true sampling mode needs ~8-10 function edits in `generate_instructions.rs` plus an integer damage rewrite for Showdown parity.

## 1. State model
- `State` (`src/state.rs:1320-1330`): `side_one`, `side_two`, `weather`, `terrain`, `trick_room`, `team_preview`, `use_last_used_move`, `use_damage_dealt` (the two flags gate optional bookkeeping, `genx/state.rs:1517-1550`). `#[derive(Debug, Clone)]` only, no Copy.
- The `src/state.rs` + `src/genx/state.rs` split: generic structs are in `src/state.rs`, gen-specific logic (options, switching, stats) in `src/genx/state.rs`. Gens 1-3 have their own whole engine trees (`src/lib.rs:1-14`); everything else, including champions, is `genx`.
- `Side` (`src/state.rs:1055-1080`): `active_index`, `baton_passing`, `shed_tailing`, `pokemon: SidePokemon` (`[Pokemon; 6]`, `:414-416`), `side_conditions`, `volatile_status_durations`, `wish: (i8,i16)`, `future_sight: (i8, PokemonIndex)`, `force_switch`, `force_trapped`, `slow_uturn_move`, `volatile_statuses` (u128 bitset, `:189`), `substitute_health`, seven boost fields (atk/def/spa/spd/spe/acc/eva; boosts live on the Side, not the Pokemon), `last_used_move`, `damage_dealt`, `switch_out_move_second_saved_move`.
- `Pokemon` (`src/state.rs:851-877`): id, level, types + base_types, hp/maxhp (i16), ability + base_ability, item, nature, `evs: (u8 x6)`, five raw stats (i16), status (one of NONE/BURN/SLEEP/FREEZE/PARALYZE/POISON/TOXIC, `:122-133`), `rest_turns`, `sleep_turns`, `weight_kg`, `mega_evolved`, `terastallized`, `tera_type`, `moves: PokemonMoves` (4 slots `m0..m3`, `:592-597`).
- `Move` (`src/state.rs:540-546`): `id`, `disabled`, `pp: i8`, and `choice: Choice` (the whole move data blob is copied into every move slot). `Choice` (`src/choices.rs:20521-20546`) holds accuracy/base_power f32, boost, flags (16 bools, `:19436-19453`), drain/recoil/crash, heal, status, volatile_status, side_condition, `secondaries: Option<Vec<Secondary>>` (heap), target. Static move table `MOVES: LazyLock<HashMap<Choices, Choice>>` (`choices.rs:11`), ~20.7k lines of hand-written Rust.
- Side conditions (`src/state.rs:600-620`): aurora_veil, crafty_shield, healing_wish, light_screen, lucky_chant, lunar_dance, mat_block, mist, protect, quick_guard, reflect, safeguard, spikes, stealth_rock, sticky_web, tailwind, toxic_count, toxic_spikes, wide_guard (i8 counters). Weather/terrain/trick room each have a `turns_remaining` (`:732-784`). Durations: confusion, encore, lockedmove, slowstart, taunt, yawn (`:786-794`).
- Not represented (verified by absence in structs): hidden/known info, move-history beyond `last_used_move`, PP-up/Max PP, per-mon boosts after switch (boosts reset), Gigantamax/Dynamax, Z-moves, doubles (single active slot per side), Item Clause (a team-builder concern), turn counter, RNG state, perish song/other counters beyond the durations listed, weather/terrain source mon.
- Size / copy cost: `State: Clone`, deep. Per Pokemon 4 `Move`s each with a `Choice` (many f32/Option fields + an `Option<Vec>`), so cloning one State means 48 `Choice` clones and a heap alloc per move with secondaries. I estimate 10-15 KB per State (inferred, not measured). The engine avoids clones in the hot path by mutating in place and undoing via instruction reversal (`state.rs:1788-2190`, `apply_instructions` / `reverse_instructions`), so "copy the state per rollout step" is NOT the engine's design; a training loop should use apply/reverse or accept one clone per battle.
- Interface to Python is a string: `State::serialize/deserialize` (`src/state.rs:2220-2434`, format `side1/side2/weather/terrain/trick_room/team_preview`). Deserialize rebuilds each `Move.choice` by `MOVES.get(...)` (`:551-562`). The existing `pe_ext` does string state in/out per call.

## 2. How a turn resolves
- Entry point: `generate_instructions_from_move_pair(state, &MoveChoice s1, &MoveChoice s2, branch_on_damage) -> Vec<StateInstructions>` (`src/genx/generate_instructions.rs:4065`). It takes ONE choice per side, so "both sides choose" = the caller picks both choices then calls this once. `MoveChoice` = `MoveTera | MoveMega | Move | Switch | TeamPreview(lead, r1, r2) | None` (`genx/state.rs:~52-59`).
- Order inside (`:4065-4350`):
  1. BSS team preview short-circuit (`:4071-4090`, `generate_instructions_for_bss_team_preview` `:3988`): switches in the leads, runs on-switch-in abilities/items by effective speed (strict `>`, tie goes to side two, `:4012-4018`), faints the 3 unchosen mons via `TeamPreviewFaintIndex`, toggles `team_preview`. Deterministic (one branch).
  2. Build `Choice` from the chosen move slot (clone), mark tera/mega flags (`:4094-4160`).
  3. Pursuit-vs-switch special path (`:4175-4210`, `:4357`).
  4. Switches run first (`generate_instructions_from_switch`, `:239`), then tera, then Mega Evolutions (`run_mega_evolutions` `:3885`; both sides mega: faster first, tie goes to side two with a comment admitting the missing branch, `:3890-3897`).
  5. `modify_choice_priority` (`:2603`: Grassy Glide, Prankster, Gale Wings, Triage) then `moves_first` (`:2623`).
  6. `handle_both_moves` (`:3846`): first mover `generate_instructions_from_move`, `after_move_finish` (White Herb), then for each resulting branch the second mover.
  7. For each branch: apply, `add_end_of_turn_instructions` (`:2854-3606`), reverse. End of turn is skipped if either side is replacing a fainted mon or has `force_switch` (`:4260-4270`, `:2860`).
- Ordering rules (`moves_first`, `:2623-2710`): switches before moves (except Pursuit); priority compare; Custap Berry; `get_effective_speed` (`:2535-2600`) with weather-speed abilities, Unburden, Quick Feet, Slow Start, Protosynthesis/Quark Drive, Tailwind, Iron Ball, Choice Scarf, paralysis; Trick Room reverses; equal speed returns `SpeedTie` which branches 50/50 (`:4297-4340`). Speed is an integer truncation of an f32 product (`:2598`), so Showdown's per-step rounding may differ (inferred).
- Before-move: `before_move` (`:1676`) runs ability/item/choice hooks that rewrite the `Choice` (not the state), then Protect/Spiky Shield etc. strip effects. `generate_instructions_from_move` (`:2039`) then handles: Encore forced move, Taunt countdown, "target already forced to switch" early out, charge moves, PP decrement, Sleep/Freeze/Para/Confusion/Protect-chain checks (`generate_instructions_from_existing_status_conditions` `:1796`), Sleep Talk, `move_has_no_effect` (`:1589`), `cannot_use_move` (`:1625`: Taunt, Flinch, Heal Block, target at 0 hp), special effects, accuracy (`check_move_hit_or_miss` `:1210`), damage, `run_move` (`:3607`: hits, side conditions, volatile status, status, heal, boosts, drag, pivot toggles, secondaries).
- Pivot/forced switch: pivot moves set `force_switch` on the user plus `switch_out_move_second_saved_move` to remember the opponent's pending move (`:3695-3790`). The next call to `get_all_options` returns only switches for that side and a stored move/None for the other (`genx/state.rs:1226-1250`). Fainted replacement: if active hp <= 0 the side gets switch options and the other gets `None` (`:1252-1270`); both fainted = both pick switches.
- Drag moves (`get_instructions_from_drag` `:1273`) branch uniformly over alive bench mons.
- End of turn (`:2854`): sides are processed `[first_move_side, other]` (`:2862`), not re-sorted by speed (inferred difference from Showdown's speed-sorted residual order under Trick Room/priority).

- Damage detail: the move flow calls `calculate_damage(... DamageRolls::Max)` (`:2250`) then derives min = 0.85 x max, average = 0.925 x max (`:2415-2417`), so damage is one number, a float product ending in `as i16` truncation; Showdown applies integer floors at each modifier step and picks 1 of 16 rolls. With `branch_on_damage == true` and a kill possible, it splits into "kill" (prob = fraction of the 16 rolls that kill via `compare_health_with_damage_multiples`, `:1038-1058`, merged with crit chance) and "non-kill at average-of-non-kill-rolls" (`:2418-2452`); if no kill possible it splits into crit (BASE_CRIT_CHANCE 1/24 in Champions, `:52-56`) vs non-crit (`:2454-2471`). Otherwise (`branch_on_damage == false`) it is always the 0.925 average and crits never happen unless the move guarantees them (`:2472-2477`).
- `branch_on_damage` is set by the caller: the Python `generate_instructions` always passes `true` (`poke-engine-py/src/lib.rs:1067`); MCTS passes true only at the root and its children (`src/mcts.rs:150`, "should_branch_on_damage = self.root || parent.root").
- Pruning/caps: none in the engine. `combine_duplicate_instructions` merges equal instruction lists (`:2520-2533`). A feature `remove_low_chance_instructions` is declared (`Cargo.toml:21`) but I found no `cfg` use of it in `src/` (grep returned nothing), so it is a dead flag in this checkout. Per-turn branch count can multiply (speed tie x miss x secondary x crit) but is bounded by the events above.
- Probabilities are f32 percentages (100.0 start, `src/instruction.rs:21-26`), multiplied per branch.

## 4. What it would take to sample one outcome like Showdown
Hook options:
- A. Post-hoc sampling (exists): generate all branches, pick one by percentage. Reference implementation `pe_ext/src/lib.rs:22-33` (`sample`) and used in `step`/`random_battles` (`:57-120`); same pattern in `src/mcts.rs:111-126`. Costs the full enumeration each turn and inherits every collapsed event (damage always 0.925, crit rare, multi-hit 3). Zero engine edits.
- B. Sampling mode inside the generator (recommended for training fidelity): add an RNG parameter/trait so each branching site draws instead of cloning. Sites to change, all in `genx/generate_instructions.rs`: `check_move_hit_or_miss` (`:1210`), `get_instructions_from_secondaries` (`:1060`), `generate_instructions_from_existing_status_conditions` (`:1796`, para/thaw/sleep/confusion/protect), speed-tie arm of `generate_instructions_from_move_pair` and `run_mega_evolutions` (`:3885`), `get_instructions_from_drag` (`:1273`), Sleep Talk (`:2308`), the damage/crit block (`:2400-2480`), `run_move` multi-hit loop (`:3607-3640`), plus the end-of-turn random bits in abilities/items (not enumerated). That is about 8-10 functions plus the signature plumbing (`generate_instructions_from_move` and `run_move` pass many params already).
- New code needed for collapsed events: real 16-roll damage with Showdown's integer chain (`damage_calc.rs` `common_pkmn_damage_calc` `:~540-600` and `calculate_damage` `:612`, roughly 600 lines of the 1467-line file touched/rewritten), per-hit crit draws, 2-5 multi-hit distribution (35/35/15/15), per-hit accuracy for Triple Axel/Population Bomb, Outrage 2-3 turn draw, confusion duration 2-5 (needs a counter plus end-of-turn decrement), sleep duration draw at application time (Champions rule), random-move effects if any are in the format, and Showdown's PRNG call ORDER if bit-exact replay is wanted.
- Rough size (inferred): B plus damage rewrite is a few hundred to ~1500 changed lines in 3 files (`generate_instructions.rs`, `damage_calc.rs`, `choice_effects.rs`), plus tests. A thin wrapper around a per-battle loop with apply/reverse (not clone) is another few hundred lines.
- Forcing a specific outcome: not supported today. With A you can force by selecting a branch index (and the branch list is deterministic for a given state/choices), good for branch-level differential tests ("does the engine contain the Showdown outcome with right probability"). For bit-exact replay of a scripted Showdown PRNG, the engine's outcome space does not line up (damage is one average, sleep is per-turn wake probability rather than a drawn duration, multi-hit is fixed), so you would need mode B with a draw interface that mirrors Showdown's PRNG call order.

## 5. Legal options
- `State::root_get_all_options` (`genx/state.rs:~1180`) -> `get_all_options` (`:1226`). Team preview (bss): 20 combos x 3 leads = 60 `TeamPreview` choices per side (`:822-845`, test `tests/test_bss_mechanics.rs:23-29`). Non-bss team preview offers a Switch per mon.
- Moves (`add_available_moves`, `genx/state.rs:491-534`): skip `disabled` or `pp <= 0`; Encore restricts to last used move; Blood Moon / Gigaton Hammer cannot repeat; Assault Vest or Taunt exclude status moves. Mega adds a `MoveMega` duplicate for every move when the side has not mega-evolved and the holder has a matching stone (`can_use_mega` `:1095-1104`, `can_mega_evolve` `:307-316`, comment admits it ignores "another mon already mega'd" at the mon level but the side-wide `can_use_mega` check covers it). Tera adds `MoveTera` only if `terastallization` feature (`:1086-1092` area; `#[cfg(not(feature = "terastallization"))] can_use_tera() -> false`), and `terastallization = ["gen9"]` (`Cargo.toml:43`), so under `champions`/`bss` Tera is off.
- Choice lock: implemented through `disabled` flags: Choice Band/Specs/Scarf disable the other moves when a move is used (`genx/items.rs:793-799`, `get_choice_move_disable_instructions` `:286-301`); Disable has an effect volatile but no code disabling a move slot (`DISABLE` only in `genx/state.rs:775`, my reading: no legality effect).
- Switches: any alive non-active mon (`add_switches`, `:1106-1116`), removed if `trapped` (`:1118-1148`: locked move, NoRetreat, partially trapped/Trapped unless Ghost/Shed Shell, Shadow Tag, Arena Trap vs grounded, Magnet Pull vs Steel). Forced-trap override `force_trapped` and `slow_uturn_move` in `root_get_all_options` (`:1190-1230`). Must-recharge and charging moves give a single forced option (`:1281-1320`).
- PP and Struggle: PP is decremented only when the move's pp < 10 (`generate_instructions.rs:2230-2245`, comment "most of the time pp decrement doesn't matter"), so a 16-PP move never runs out in the engine; a move at 0 PP is unselectable, and with no moves left the option list is empty so it falls back to `MoveChoice::None` (`:1322-1327`). `Choices::STRUGGLE` exists as data (`choices.rs:16374`) but is never offered (grep of `genx/*.rs` found no use). No Struggle recoil mechanic.
- Default PP is 32 (`src/state.rs:564-572`).

## 8. Extension points and fork friendliness
- Data is hand-written Rust, not generated at build time: one huge `MOVES` constructor (`choices.rs`, 20,774 lines, `Choices` enum via `define_enum_with_from_str!` macro `src/lib.rs:21-120`), `PokemonName` (`pokemon.rs`, 1503 lines), `base_stats.rs` (713), abilities (2942 lines, 302 `Abilities::` references), items (1552). `cfg(feature)` branches are scattered inline, so Champions diffs are small local patches but numerous.
- Behaviour is dispatched by big `match` statements keyed by `Choices` / `Abilities` / `Items` in `choice_effects.rs` (1773), `abilities.rs` (hooks: `ability_before_move :536`, `ability_after_damage_hit :707`, `on_switch_out :1049`, `end_of_turn :1179`, `on_switch_in :1400`, `modify_attack_being_used :1861`, `modify_attack_against :2318`), `items.rs`. Adding or fixing a move/ability/item = add a match arm plus data row; low coupling. A fork that only patches data and adds arms stays rebase-friendly (inferred); a sampling mode touches the core generator and will conflict with upstream.
- Mechanism: effects are expressed by mutating the `Choice` before use (modify-the-move pattern) and by pushing `Instruction`s (`src/instruction.rs:44-103`, ~50 variants) that are both applied and reversible (`state.rs:1794-2190`). Any new state field needs: struct field, serialize/deserialize, new Instruction variant if mutated, apply + reverse arms, and a pyo3 field if exposed.
- Python bindings (`poke-engine-py/src/lib.rs`, 1142 lines): `generate_instructions` (`:1045`), `calculate_damage` (`:1077`), `mcts`, `id`, State/Pokemon classes (PyPokemon has mega_evolved/terastallized/tera_type fields, `:705-735`). It exposes no legal-options, evaluate, or battle-over call, which is why `pe_ext` (146 lines) exists. `pe_ext` exposes options, evaluate, battle_over, `step` (string state in/out with seeded sampling) and native `random_battles`.
- Search layer (`search.rs` 235, `mcts.rs` 360, `mcts_threaded.rs` 478) is separable from the engine and can be dropped from a training fork.

## 9. Surprises a planner must know
1. Damage is not Showdown-exact: single float chain, average roll only (0.925 x max), truncation to i16; prior check 172/220 exact, 11 off by >5% (`notes/poke-engine-eval.md`, Make It Rain 62 vs 49, Disguise 0 vs 44).
2. Crits effectively do not happen in plain sampling (only a 1/24 branch when `branch_on_damage` and no kill possible, or a split with kill rolls); damage variance is absent, so kill thresholds are deterministic except in that branch.
3. Multi-hit always 3 hits (Skill Link 5); secondaries apply once per move even for multi-hit; Triple Axel/Population Bomb accuracy only checked once.
4. Confusion never expires on its own (no duration use in genx); Outrage-family always 3 turns; Encore/Taunt fixed 3.
5. No Struggle; PP only tracked below 10 PP (higher PP never decrements), Pressure only matters then; `pp` defaults to 32; moves with PP <= 0 vanish from options.
6. Disable and Torment, Metronome/Assist/Copycat/Mirror Move/Nature Power have no effect in code I could find (data rows only).
7. Mega ordering: if both sides mega, speed tie goes to side two (documented missing branch, `generate_instructions.rs:3890-3897`); Mega gate is side-wide (`can_use_mega`).
8. BSS team preview is deterministic and happens inside the engine as a special move pair; unchosen mons are set fainted (so `battle_is_over` works on 3 mons: `src/state.rs:1359-1370`). No Item Clause or species-clause checking, no team validation.
9. Boosts live on `Side`, so Baton Pass/Shed Tail keep them and everything else resets via instructions on switch.
10. `remove_low_chance_instructions` feature is declared but unused; there is no branch cap or pruning, and probabilities are f32.
11. Earlier eval found unimplemented abilities used by the ladder pool (Stance Change, Cursed Body, Symbiosis, Imposter, Super Luck, Frisk, Cute Charm, Illusion, Electromorphosis, Moody, Harvest, Rivalry, Unnerve, Early Bird) and items (Light Clay, Terrain Extender, Damp Rock, Scope Lens, Quick Claw, Eject Button, Red Card, Heat Rock, Smooth Rock, Zoom Lens, Bright Powder, Big Root, King's Rock) in `notes/poke-engine-eval.md`; I did not re-verify these against this checkout.
12. Measured throughput from the earlier eval (not re-run): 12.3k battles/s single process native loop and 201k battles/s on 24 processes with random policies, vs ~147 battles/s via Python string-state stepping, vs Showdown 7/s per process (`notes/poke-engine-eval.md`). The Python/string boundary dominates, so a training fork should keep state native and expose batched step calls.
